# heypcb.ai 竞品深度分析

> 分析对象：https://heypcb.ai/（AI PCB 设计工具，2026-10）
> 分析维度：生成能力 · 工程逻辑 · 知识产权保护
> 数据来源：官网首页、定价页、Challenge 页、Blog（MCP / Time Machine / Comment / Multiplayer / Explore）、Terms of Service、Privacy Policy、/licences 开源库归属页

---

## 0. 一句话定位

**heypcb = 用自然语言描述一台机器，AI（"Inky"）把它变成一套真实、可制造、可编辑、归你所有的 KiCad 工程文件。**

它的核心承诺贯穿全站："**Files you keep**（文件你保留）" 与 "**Build something real**（造点真东西）"。这意味着它卖的不是"一张漂亮的渲染图"，而是**可携带、可编辑、可交给任何 PCB 厂的工程资产**。

## 1. 生成能力（Generation Capabilities）

### 1.1 端到端生成链路

从"一句话需求"到"可制造文件"的完整闭环，而不是单点工具：

```
自然语言描述 → 原理图(schematic) → 布局(layout/布线) → 制造文件(fab/Gerbers/STEP)
                                                              ↓
                                          真实 KiCad 工程文件（.kicad_sch / .kicad_pcb）导出
```

关键点：**输出物是 KiCad 原生文件，不是私有格式、不是截图、不是网页渲染图**。这是它与"AI 画 PCB 效果图"类产品的本质分界。

### 1.2 AI 智能体 "Inky"

- **对话式设计 agent**：Inky 不只是聊天，它能直接对板子执行动作——放置器件、布线、铺铜、改层、旋转器件。
- **努力程度分级**（定价里体现的核心能力杠杆）：
  - Low / High → Starter 档
  - Max → Pro 档
  - Ultra → Max 档
  - 本质是"一回合里 agent 自主干多少活、多想几步"。
- **Python 沙盒（Pro 及以上）**：Inky 可以**写代码跑精确计算**（如电流/线宽/温升、阻抗、分压等），而不是靠语言模型"拍脑袋"。代码在隔离临时环境执行，跑完即销毁。这是把 LLM 的"不确定输出"接上"确定性计算"的关键工程手段。
- **多模态输入**：可基于图片/参考图做板形（如"做成某角色/动物/产品的形状"），后台 web 搜图作为参考。
- **3D 生成 + 外壳设计**：可生成 3D 预览和自定义外壳（enclosure），与板子联动。
- **Comment（指哪问哪 / 指哪改哪）**：把问题"钉"在原理图/PCB/3D 的任意器件或网络上，Inky 从**设计本身**回答（如"U23 是 LPC4320 微控制器，负责控制与数字接口"）；且**每条评论可转成指令**让 Inky 直接改板（案例：在 HackRF One 背面加二维码）。

### 1.3 MCP 集成（把 PCB 能力开放给任意 AI agent）

- `claude mcp add --transport http heypcb https://api.heypcb.ai/mcp`
- 兼容 20+ MCP 客户端：Claude Code / Codex / Cursor / ChatGPT / VS Code / Gemini CLI / OpenCode / Zed 等。
- 让外部编码 agent 能"顺便把板子也设计了"——这是很聪明的分发策略：**寄生在别人家的 agent 生态里获客**。
- 官方案例：Claude Code 生成 8×8 RGB 显示板（ESP32-S3 + 64 颗 WS2812B，145 个器件），最终 **0 DRC / 0 ERC / 0 未连网络，且 KiCad 自身的 DRC 也报零错误**——用"第三方工具验证"来证明生成质量的可信度。

### 1.4 质量可信度（"Before you order"）

首页专门一节强调三个信任锚点：

1. **Real parts（真实器件）**：verified libraries、pin maps、datasheet limits，而非占位 footprint。
2. **A real pass（真实校验）**：电气、布局、制造检查作用于**实际设计**，且给出**修复**而非只报错。
3. **Yours to keep（归你所有）**：Gerbers、STEP、可编辑 CAD，任意 fab、任意工具可用。

## 2. 工程逻辑（Engineering Logic / Architecture）

### 2.1 数据格式选型：押注 KiCad

- 所有设计存为 **KiCad 原生工程**，导出 Gerber（制造）、STEP（结构）。
- **为什么这是核心工程决策**：
  - KiCad 开源、无许可费，可自建渲染/解析/校验管线；
  - 文件可携带 → "files you keep" 承诺成立，无 vendor lock-in；
  - 可直接被第三方验证（KiCad 自身 DRC），形成质量背书闭环；
  - 生态里已有海量开源硬件（GitHub 上的 KiCad 工程）可被导入，喂给 Circuit World。

### 2.2 AI 编排（Agent Loop）

从隐私政策可反推出其 agent 运行架构：

- **工具执行架构**：Inky 每回合决定调用哪些设计工具（放置/布线/DRC/导出…），作用于板子，逐轮迭代直到满足。
- **代码执行**：跑在隔离、临时、用完即删的沙盒环境，结果留存到板子（像聊天记录一样）。
- **Web 检索**：查器件（catalogue lookup，去标识化）、查参考图、查开源板。
- **模型路由**：不同消息可能路由到不同第三方模型供应商（明确不依赖单一模型）。
- **撤销能力**：agent 对板子的每一次改动都可在编辑器撤销（降低自动化风险）。

### 2.3 校验闭环（不是"生成完就撒手"）

- 三层校验：**电气（ERC）→ 布局（DRC）→ 制造（DFM，real fab rules）**。
- 关键差异点：**"with fixes instead of just flags"**——发现问题的同时给出修复，而非只报红叉。
- 出货前用真实器件库 + 真实工厂规则过一遍，才允许下单打样。

### 2.4 协作与版本工程

- **Multiplayer（多人实时协同）**：同板多人 live 光标/选中/拖拽/布线/视角跟随，邀请制 + 编辑/只读权限 + 光标颜色。路由可实时被旁观。
- **Time Machine（硬件版版本控制）**：每次原理图/PCB/AI 编辑进同一时间线，可回放、定位是谁哪一步引入问题、恢复到任意版本。**AI 的编辑连同触发它的 prompt 一起入库**——这既是质量工具，也是审计/IP 追溯工具。
- 权限边界清晰：项目链接本身无权限，必须邮箱邀请。

### 2.5 生态飞轮（获客与内容供给的正循环）

- **Circuit World**：11,000+ 已发布开源硬件板目录，按"围绕哪颗主芯片"索引（ESP32 / Arduino / RP2040 / nRF52 / STM32 / RISC-V…），可一键打开、fork、二次开发。
- **Explore**：把目录做成"可缩放的硬件地图"，从分类→具体板逐级下钻。
- **Challenge（挑战赛）**：$2,000 奖金（最受欢迎 + 最佳板各 $1,000），用真金白银驱动用户持续产出公开板——**内容是它的护城河，比赛是它的内容引擎**。
- **代下单打样**：工厂在中国，价格透明、工厂复审（factory review），把"生成→制造"最后一段也闭环了。

### 2.6 计费工程（能力即价格锚点）

| 档位 | 价格 | 关键差异 |
|---|---|---|
| Starter | $20/mo | 10 项目 / 10 下载 / 5 协作者 / Low+High |
| Pro | $60/mo | 无限项目与下载 / 10 协作者 / +Max / +Python 沙盒 |
| Max | $200/mo | 20 协作者 / +Ultra |
| Ultra | $500/mo | 最高 AI 用量 |

- 计费杠杆 = **AI 工作量 × 努力等级 × 项目数 × 下载数 × 协作者数 × 沙盒**，层层递进。
- 免费试用是"一块板子上的固定 Inky 用量"，用完才引导付费，**绝不自动转付费、绝不自动扣款**——降低信任门槛。

### 2.7 隐私工程（合规 + 信任基建）

- 分析脱敏：不记录 email/姓名/prompt/回复/器件号/网络名/几何。
- Session replay 全掩码（字段/画布/图片全屏蔽），且 Do-Not-Track / GPC 一票否决；EU/EEA/UK 默认关。
- 数据保留分级：学习记录 1 年、账单 7 年、日志 30 天、备份 35 天滚动。

## 3. 知识产权保护（IP Protection）

这是 heypcb 做得最成体系、最值得学习的一块。它**同时保护三方**：用户、开源作者、heypcb 自己。

### 3.1 保护"用户"的知识产权（核心信任卖点）

1. **所有权归用户**（Terms §4）：项目文件、prompt、设计、导出 Gerbers/KiCad 归档，**你保留完整所有权**；heypcb 只拿"为运营所必需"的有限许可，**明确不主张你的板子的任何所有权**。
2. **不拿数据训练模型**（Privacy §3，最关键的一条）：
   > "We do not use your project files to train public foundation models, and we do not fine-tune any model on your data."
   这是 B 端/专业用户最敏感的 IP 问题，直接写死。
3. **文件可携带**：KiCad 原生 + Gerber + STEP，随时整体导出、随时离开——用"不锁死你"来证明"你的资产就是你的"。
4. **学习记录的脱敏与隔离**（Privacy §3）：即使为了改进质量留存 Inky 会话技术记录，也**只留 redacted 版**，且跨账号只共享"通用工程指引"；任何"命名了你项目 / 板子器件 / 网络名"的指引在入库前被拒绝。你的设计细节永远不外泄。

### 3.2 保护"开源生态/第三方"的知识产权（合法合规做开源库）

1. **开源库完整归属**（/licences 页）：逐一列出库名、作者、许可证、源码 commit hash、**做了哪些改动**（重命名 ID、修正 footprint 名、重指 3D 路径，pad 几何不动）。符合 CC-BY-SA 的"标明改动"义务。
2. **"传染性"隔离（关键合规设计）**：引用 **KiCad library exception**——"把库里的一个 footprint 放到你的设计里，**不会**让你的板子被 share-alike 传染"。你的板子、原理图、制造文件依然归你（Terms §10）。这消解了开源许可证在商用场景最大的恐惧。
3. **导入开源板（Circuit World）的合规**（Terms §6）：
   - 一律标注 imported、作者、仓库链接、许可证；
   - 无许可证 → 标"All rights reserved"，**不给 fork 按钮**；
   - 无法分类的许可证 → 如实说明并指向原文件；
   - **claim 机制**：作者可用 GitHub 账号认领，认领后掌控 listing（含下架）；
   - 任何人不需账号、不需理由即可要求下架（发邮件即可）。
4. **发布到 Circuit World 的授权模型**（Terms §5）：发布 = 复制成"公开快照"，授予全球免版税许可（因为"已下载的设计无法被召回"）；但你随时可撤回快照（停止展示），只是不追溯已下载的副本。

### 3.3 保护"heypcb 自身"的知识产权

1. Service 本身（软件、品牌、UI、文档、非用户内容）归 heypcb 及其授权方（Terms §10）。
2. 禁止反向工程、爬取、绕过限制、滥用（Terms §3）。
3. 商标声明：Espressif / Arduino / RPi 等商标仅为说明"板子围绕哪颗芯片"，无背书暗示（规避商标侵权）。
4. **争议解决**（Terms §19）：仲裁 + 放弃集体诉讼/陪审团；**IP 侵权可例外直接申请禁令救济**。
5. **DMCA 流程**（Terms §11）：标准六要素投诉 → 下架 → 反通知 → 重复侵权者封号。

### 3.4 责任边界（IP 之外的合规防线）

- **工程责任归用户**（Terms §7）：AI 输出可能不完整/不可制造/不安全，heypcb 是"设计辅助"而非替代工程师，用户必须自审。这既保护 heypcb，也界定了"AI 生成物"的法律性质。
- **代下单时的版权校验**（Terms §21）：对第三方设计的板，只在不禁止商业用途的许可证下才允许下单制造；无许可证/禁商用/无法分类的，拒绝制造；CERN-OHL 等要求"源码位置随产品走"的，明确要求遵守。fork 后的板版权用户自负。

## 4. 三个维度的底层方法论总结

| 维度 | heypcb 的做法 | 一句话方法论 |
|---|---|---|
| **生成能力** | 端到端 + agent 自主执行 + 沙盒精确计算 + KiCad 原生输出 | "让 AI 直接操作真实工程文件，而不是生成一张图" |
| **工程逻辑** | 工具执行 loop + 三层校验闭环 + 版本时间线 + 生态飞轮 | "用确定性校验兜住 LLM 的不确定性，用内容生态锁住用户" |
| **IP 保护** | 用户所有权 + 不训练模型 + 文件可携带 + 开源合规 + 传染隔离 | "把'你的资产永远是你的'做成产品卖点，而不只是法律条款" |

## 5. 可迁移的启示（对我们 / BMC 的借鉴）

1. **输出"真实格式"而非"渲染效果"**：生成物要能被第三方工具独立验证、能被用户带走，这本身就是最强有力的信任证明。
2. **确定性计算兜底**：让 agent 用沙盒跑代码算精确值，是 AI 生成"从玩具到可用"的关键一跳。
3. **把"不用你的数据训练模型"做成首屏级承诺**：这是专业用户付费的前提，值得单独写进隐私政策并反复强调。
4. **开源/第三方内容的合规要"可追溯"**：来源 + 作者 + 许可证 + commit hash + 改动说明 + 认领/下架机制，缺一不可。
5. **主动隔离"传染性"风险**：找到开源许可证里的 exception 条款，明确"用 ≠ 被传染"，是打消商用顾虑的利器。
6. **让"内容"成为护城河**：用比赛、目录、地图、可 fork 生态持续制造公开内容，内容即获客。
7. **计费按"能力杠杆"分层**：努力等级 / 沙盒 / 协作者数 / 下载数，让价值可感知、可升级。
8. **责任边界写清楚**：AI 生成物"不保证可制造"，用户自审——既是法律防线，也是行业成熟度信号。
