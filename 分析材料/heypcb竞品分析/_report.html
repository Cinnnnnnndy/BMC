00一句话定位

heypcb 卖的不是「一张漂亮的 PCB 渲染图」，而是一套真实、可制造、可编辑、归你所有的 KiCad 工程文件。全站两条反复出现的主线：「Files you keep」（文件你保留） 与 「Build something real」（造点真东西）。

输入

一句话自然语言描述「你正在造的机器」

过程

AI agent 自主完成原理图 → 布局 → 校验，可多人/AI 协作

输出

真实 .kicad_sch / .kicad_pcb + Gerber + STEP + BOM，任意 fab/工具可用

核心承诺输出物可被第三方工具（KiCad 自身）独立验证、可整体带走，这本身就是最强有力的质量与信任证明。

01开源情况速答

结论：开源了「接入层」，核心工程内核仍是黑盒。

组件是否开源说明
MCP 客户端包 @heypcb/mcp / HeyPCB/heypcb-mcp开源 · MITTypeScript，30★。npm 包 + GitHub 仓库。
MCP 本地 server（npx -y @heypcb/mcp）开源README 原话：「has no design logic of its own」——只把工具透传到远程服务器，另加本地文件工具。
Inky 设计 agent / 器件库 / 电路模块库 (add_block)不开源跑在 heypcb 私有服务器 api.heypcb.ai/mcp。
布局/布线/铺铜引擎、DRC/ERC、fab 检查不开源核心护城河，全部远程执行。
策略解读开放 MCP = 开放「分发渠道」（寄生在 Claude Code / Cursor / Codex 的 agent 生态里获客）；闭源工程内核 + 器件库 + 已验证电路块，才是它不愿意交出去的资产。

Inky —— 会「动手」而不只是「聊天」的 agent

  • 对话式设计 agent：能直接对板子执行动作——放置器件、布线、铺铜、换层、旋转器件。
  • 努力程度分级（计费核心杠杆）：Low / High → Starter，Max → Pro，Ultra → Max；本质是「一回合里 agent 自主干多少活」。
  • Python 沙盒（Pro+）：Inky 可写代码跑精确计算（线宽/温升/阻抗/分压），用确定性计算兜住 LLM 的不确定输出。代码在隔离临时环境跑完即删。
  • 多模态：可依据图片/参考图做板形（后台 web 搜图）。
  • Comment（指哪问哪 / 指哪改哪）：把问题钉在任意器件/网络，Inky 从设计本身作答；每条评论可转成指令直接改板。

03工程逻辑

数据格式选型：押注 KiCad

所有设计存为 KiCad 原生工程（S-expression 纯文本 .kicad_sch / .kicad_pcb），导出 Gerber（制造）与 STEP（结构）。

  • 开源、无许可费，可自建渲染/解析/校验管线；
  • 文件可携带 → 「files you keep」承诺成立，无 vendor lock-in；
  • 可被官方 kicad-cli 独立验证 → 形成零误差质量背书；
  • 生态里已有海量开源 KiCad 工程可导入，喂给 Circuit World。

AI 编排（Agent Loop）

工具执行架构

每回合决定调用哪些设计工具（放置/布线/DRC/导出），逐轮迭代直到满足；每步可撤销。

代码执行

跑在隔离、临时、用完即删的沙盒；结果留存到板子（像聊天记录）。

Web 检索

查器件（catalogue lookup 去标识化）、查参考图、查开源板。

模型路由

不同消息可路由到不同第三方模型供应商，不依赖单一模型。

校验闭环 + 协作版本

  • 三层校验：电气（ERC）→ 布局（DRC）→ 制造（DFM / 真实 fab 规则），且「检查即修复」。
  • Multiplayer：多人实时协同（live 光标/选中/拖拽/布线/跟随），邀请制 + 编辑/只读 + 光标颜色。
  • Time Machine：硬件版版本控制——每次原理图/PCB/AI 编辑进同一时间线，可回放、定位引入问题的编辑、恢复任意版本；AI 的编辑连同触发它的 prompt 一起入库（既是质量工具，也是审计/IP 追溯工具）。

生态飞轮 & 计费

生态飞轮：Circuit World（11,000+ 开源板，可 fork）→ Explore（可缩放硬件地图）→ 挑战赛（$2,000 奖金驱动用户持续产出公开板）→ 代下单打样（工厂复审，闭环到制造）。内容是护城河，比赛是内容引擎。

04形式转换是怎么做的（技术原理）

heypcb 的「转换」不是格式翻译，而是一个中心设计模型的不同视图/序列化。它内部维护一份 KiCad 兼容设计模型，schematic / PCB / 3D / Gerber 都是同一模型的投影。

中心模型设计模型 = 器件实例（symbol + footprint 映射） + 网表（连接关系） + 物理坐标 + 铜几何。Schematic 是它的「逻辑投影」，PCB 是「物理投影」，3D 是「渲染投影」，Gerber/STEP/BOM 是「制造序列化」，网表是「中间提取」。

为什么选 KiCad（技术底座）

  • 文件开放且纯文本：.kicad_sch / .kicad_pcb 是可读 S-expression 文本 → agent 能直接读写/编辑真实设计，而非生成一张图。
  • 官方 kicad-cli 兜底：本地校验（check_local）与导出（export_local）直接调用 KiCad 8+ 的 CLI，权威、零误差、可离线。
  • 文件边界清晰：upload_kicad_project 上传的是 board、schematic 层级、.kicad_pro、.kicad_dru、库表与项目本地库（≤50MB，不含 3D 模型/备份）。
一句话heypcb 没发明格式，而是寄生在 KiCad 生态上：用开源格式做设计资产，用官方 CLI 做零误差校验导出，把 AI 的「不确定生成」接上「确定性的工程验证」。

05知识产权保护

heypcb 成体系地同时保护三方：用户、开源作者、heypcb 自己。

① 保护「用户」的知识产权（核心信任卖点）

手段条款/事实
所有权归用户Terms §4：项目文件、prompt、设计、导出 Gerbers/KiCad 归档，用户保留完整所有权；heypcb 只拿「运营所需」的有限许可，明确不主张板子的所有权。
不用你的数据训练模型Privacy §3 原文：「We do not use your project files to train public foundation models, and we do not fine-tune any model on your data.」 这是 B 端用户最敏感的 IP 问题，直接写死。
文件可携带KiCad 原生 + Gerber + STEP，随时整体导出、随时离开——用「不锁死你」证明「你的资产就是你的」。
学习记录脱敏与隔离Privacy §3：跨账号只共享「通用工程指引」；任何命名了你项目/器件/网络名的指引在入库前被拒绝，设计细节不外泄。

② 保护「开源生态/第三方」的知识产权（合法合规）

  • 开源库完整归属（/licences 页）：列出库名、作者、许可证、源码 commit hash、改动说明，满足 CC-BY-SA「标明改动」义务。
  • 「传染性」隔离（关键合规设计）：引用 KiCad library exception——「把库里一个 footprint 放进你的设计，不会让你的板子被 share-alike 传染」，你的板子/原理图/制造文件仍归你（Terms §10）。
  • 导入开源板合规（Terms §6）：标注 imported/作者/仓库/许可证；无许可证 → 标「All rights reserved」且不给 fork 按钮；无法分类 → 如实说明指向原文件；作者可 claim 认领并掌控 listing；任何人不需账号即可要求下架。
  • 发布授权模型（Terms §5）：发布 = 公开快照 + 全球免版税许可（因「已下载的设计无法召回」），但可随时撤回快照停止展示。

③ 保护「heypcb 自身」 + 责任边界

对象手段
自身 IPService（软件/品牌/UI/文档/非用户内容）归 heypcb（§10）；禁反向工程/爬取（§3）；商标声明「仅说明器件平台、非背书」（规避商标侵权）。
争议解决§19：仲裁 + 放弃集体诉讼/陪审团；IP 侵权可例外直接申请禁令救济。
侵权投诉§11：标准 DMCA 六要素 + 反通知 + 重复侵权者封号。
责任边界§7：AI 输出不保证可制造/安全，用户必须自审——既保护自己，也界定「AI 生成物」的法律性质。
代工版权校验§21：第三方设计的板，只在不禁止商业用途的许可证下才允许下单制造；无许可证/禁商用/无法分类的拒绝制造。
IP 方法论一句话把「你的资产永远是你的」做成产品卖点（而非只是法律条款），用「不训练模型 + 文件可携带 + 传染隔离」三个动作落地。

06可迁移启示

1. 输出「真实格式」而非「渲染效果」

生成物能被第三方工具独立验证、能被用户带走，本身就是最强信任证明。

2. 确定性计算兜底

让 agent 用沙盒跑代码算精确值，是 AI 生成「从玩具到可用」的关键一跳。

3. 把「不训练模型」做成首屏承诺

专业用户付费的前提，值得单独写进隐私政策并反复强调。

4. 第三方内容合规要可追溯

来源 + 作者 + 许可证 + commit hash + 改动说明 + 认领/下架，缺一不可。

5. 主动隔离「传染性」风险

找到开源许可证里的 exception，明确「用 ≠ 被传染」，打消商用顾虑。

6. 让内容成为护城河

比赛、目录、地图、可 fork 生态持续制造公开内容，内容即获客。

7. 计费按「能力杠杆」分层

努力等级 / 沙盒 / 协作者数 / 下载数，让价值可感知、可升级。

8. 开源「接入层」、闭源「内核」

开放 MCP 拿渠道，守住工程内核与器件库这块真正的资产。

07同类产品怎么做（基于开源信息的技术路线）

heypcb 的开源暴露，等于给了我们一份免费的产品架构教科书：MCP 仓库 MIT 开源（工具 schema 完整暴露流程），而 KiCad 生态全开源。做同类产品不用从零发明，而是「用开源拼装 + 在验证闭环与垂直场景上做深」。

核心判断heypcb 真正的护城河不是 AI agent，而是三样闭源资产：真实器件库、已验证电路模块库、打板验证通过率。这三样恰恰也是最难用开源直接替代的部分。

风险与建议① 最难的是「器件库积累 + 打板验证通过率」，不是 UI/agent——建议先聚焦一个垂直领域（如 BMC/服务器板卡）把器件和模块做深；② 复刻 heypcb 的「验证闭环」（每个 DRC/ERC finding 绑定一个修复工具调用 fixWith）是性价比最高的产品机制；③ 差异化打「本地优先/数据主权」——heypcb 全远程黑盒，而 KiCad + kicad-cli 天然可离线。

08BMC 项目 I2C 图能否用 KiCad

结论先行：要看你说的「I2C 的图」是哪种图——逻辑/管理拓扑图，KiCad 不合适（有更好的工具）；真实的 I2C 电路原理图/PCB，KiCad 完全合适，而且是 AI 生成最适合的电路类型。

维度场景 A：I2C 管理拓扑图场景 B：I2C 电路原理图 / PCB
「图」是什么BMC 的 I2C master 总线挂哪些 slave（传感器/EEPROM/FRU/CPLD）、地址分配、mux 切换真实电路：BMC 芯片引脚、上拉电阻、slave 器件封装、可打板
本质架构 / 管理链路图（数据模型）电路设计（工程模型）
KiCad 合适吗不合适 原理图编辑器有 ERC/引脚语义，画抽象拓扑很别扭完全合适 官方库有 24C02/传感器/BMC 符号封装
更合适的工具项目已有的 CSR 拓扑编辑器（Anchor→Bus→Chip/Connector）· draw.io · mermaidKiCad（+ kicad-cli 出 Gerber/DRC）
AI 生成前景数据驱动渲染（CSR JSON → 拓扑），非 AI 画图I2C 高度标准化，是最适合做成「已验证电路模块」由 AI 生成的电路
给 BMC 项目的落地建议① 画 I2C 总线连接 → 用已有的 CSR 拓扑编辑器（Anchor→Bus→Chip/Connector 天然就是 I2C 总线模型），数据驱动而非画图；② 设计真实 I2C 电路/板卡 → 用 KiCad，把「I2C 总线 + 上拉 + slave 阵列」封装成 已验证电路模块（借鉴 heypcb 的 add_block），由 AI 从拓扑数据直接生成原理图；③ 这两步打通，就是 heypcb「描述 → 真实文件」在 BMC 垂直场景的落地版本。
